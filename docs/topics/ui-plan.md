# 界面改造方案（人话版）

> 这份是给"拍板的人"看的：不解释代码细节，只讲**现在什么情况、要改成什么、先改哪里、你会看到什么**。
> 工程细节在 [ADR-0009](../decisions/ADR-0009-ui-change-strategy.md)；这份是它的白话翻译 + 执行顺序。

## 1. 一句话

**官方界面本来就是我们的源码构建出来的**——不是别人的黑盒。
所以正确做法是"做菜的时候把料放进去"，而不是"端上桌以后往盘子里补"。
DSH 只干两件事：把页面显示出来、把对话转过去。剩下的都写进源码里。

## 2. 先讲清楚：为什么"注入"会闪、会丢

打个比方：顾客已经坐下吃了，服务员再往盘子里补菜。

| 注入现在的麻烦 | 你会看到什么 |
|---|---|
| 页面每重画一次，塞进去的东西就被冲掉 | 聊两句，某个按钮/卡片突然没了 |
| 先得在页面上"找到"某个位置才能塞进去 | 官方界面一升级，我们的东西直接不出现，还不报错 |
| 每次刷新、切项目都要重新塞一遍 | 打开时闪一下，或者先空一块再冒出来 |

**改源码 = 在厨房里就把这道菜做好。** 端上来就是完整的，不会中途补，也不会掉。

源码在仓库的 `.upstream/openfilm` 里，界面本来就是用它构建的。

## 3. 目标长什么样

```text
你
 │
 ▼
DSH 面板（外壳：侧栏、边框、加载态）    ← 我们自己的代码
 │
 ▼
桥接层（Host 进程）                     ← 只做两件事：转发页面、转发对话
 │
 ▼
官方界面（我们自己构建的成品）           ← 我们要改的东西都在这里
   ├─ 聊天列（对话、项目列表、登录、引导）
   └─ Studio 编辑器（画布、时间轴、素材库）
```

**桥接层不"改造"界面，只"开门"。** 现在这一步已经通了（页面能显示、对话能用），剩下的活全在"最后一层"。

## 4. 三个做法，一张表看懂

| 做法 | 好比 | 体验 | 什么时候用 |
|---|---|---|---|
| **A. 改源码，重新构建**（推荐） | 做菜时把料放进去 | 不闪、不掉、跟官方一样顺 | **默认，所有能改的都走这条** |
| **B. 构建时加样式** | 出锅前撒调料 | 基本不闪，只能改颜色/间距 | 纯配色类改动 |
| **C. 运行时注入**（要淘汰的） | 端上桌再补菜 | 会闪、会丢、官方一升级就失灵 | 只剩一种：DSH 侧栏（我们没有它的源码） |

## 5. 改哪些、按什么顺序（这就是推荐）

排序只按一条：**"一刷新就消失"的排最前**，只是不好看的往后放。

## 6. 桥接：用什么、不造什么

你问的这点，答案是**能用官方的就用官方的**，我们只做薄薄一层：

| 事情 | 用什么 | 说明 |
|---|---|---|
| 页面显示 | Host 反向代理 + 把"入口"指向我们构建的界面 | 官方 Studio 本来就支持指定界面目录（`editorDir`），不用改它 |
| 对话（官方聊天列） | 官方自己的回调 `askAgent` | 官方页面里那个聊天框本来就来问这个方法；我们把它接到 DSH 的模型上（`src/dsh-ai.mjs`） |
| 工具/文件操作 | 官方的 `openfilmNative` 接口 + DSH 的 ACP 子进程 | ACP 是 DSH 官方给的对话通道，官方子进程跑，我们不自己发明协议 |
| 事件/消息 | 官方页面已有的挂载方式（`mountChat`、`postMessage`） | 和官方桌面版一样的接法 |

**一句话：页面是官方的、对话回调是官方的、协议是官方的，我们只负责"接线"和"改源码"。**

## 7. 每批做完，你怎么验（3 分钟）

1. 刷新页面 → 看那处东西还在不在、有没有闪；
2. 切一个项目再切回来 → 还在不在；
3. 断网或制造一次错误 → 提示卡出不出现；
4. 告诉我"第几批、哪一条、你看到的样子"，我据此修。

## 8. 代价，说在前面

- 每批要重新构建一次界面（几分钟），升级上游时要重放补丁（已有固定流程，见 [`playbooks/upstream-bump.md`](../playbooks/upstream-bump.md)）；
- 补丁会越来越多，所以每加一条都要登记、能说清"为什么不能更简单"；
- 上游哪天不再发布 Studio 源码，这条路才需要重新评估——目前没有这个迹象。
