# 路线图

> 一份路线图，不分版本碎片。**一版做一批**：攒够一个可验收的批次再发版号，不再每修一个 bug 就跳一个 0.0.x。
> 已完成的东西不写在这里（看 `CHANGELOG.md`）；这里只留「接下来要做什么」和「为什么」。
> 状态标记：`待做` / `进行中` / `已定但不急` / `待拍板`（需要产品决定，不要自己开工）。

## 下一批：0.9.1 —— 账号与登录

### 为什么

现在插件里的模型与额度全部来自 DSH 宿主；上游 Studio 自己的账号态（登录、余额、套餐）在 DSH 面板里是**不可见也不可用**的。结果是：

- 面板上偶尔能看到上游的"余额不足 / 去登录"卡片，点开是上游站点的空链接（引流出去，回不来）；
- 用户以为"我在 DSH 里登录过就能用"，实际两个账号体系是分开的；
- 想用上游账号的额度（图库、生成服务）必须离开 DSH 去浏览器。

### 要做什么

| 项 | 内容 | 验收 |
|---|---|---|
| 账号状态可见 | 面板顶部（或设置里）显示当前账号态：DSH 侧模型可用性 + 上游账号是否存在、是否登录、余额/套餐（能拿到多少显示多少） | 一眼看出"我能不能出片、为什么不能" |
| 登录入口内嵌 | 上游的登录流程**在面板里完成**（同一 iframe、同一站点），不走外链新窗口；登录成功后回跳项目页 | 不需要离开 DSH 就能登录 |
| 未登录的降级 | 没有上游账号时，纯本地功能（剪辑、抽帧、导出）照常可用；需要额度的动作（生成图片/视频/音乐）给一条明确提示，而不是失败弹窗 | 断网/未登录也能剪片 |
| 凭据边界 | 令牌**只存本机**（`<DSH_HOME>` 下，或交给上游自己的 Studio 存），不进我们的会话记录、不进日志、不进诊断 | 诊断 JSON 里搜不到任何令牌 |
| 余额卡片收口 | 上游的"去登录/下载桌面端"这类引流卡，在 DSH 里替换为本地可用的提示或隐藏 | 面板里不再出现跳走的引流入口 |

### 先要查清的四件事（动手前）

1. 上游账号态存在哪里：Studio 的 `server` 有没有账号相关路由（`/api/account*`、`/api/me`）、令牌落在哪个文件；
2. 登录页是否允许 iframe 内嵌（`X-Frame-Options` / `frame-ancestors`），不允许时的替代方案（同站点内跳转 vs 顶部提示）；
3. DSH 宿主是否已有账号概念可以复用（`sessionController` / 设置里），避免两套账号打架；
4. 我们自己的 HTTP 通道（`/api/no996-openfilm/*`）加账号读接口时的鉴权：**只允许本机 DSH 浏览器同源**（沿用现有 `ctx.connection.admit`）。

### 明确不做

- 不做用户名密码代填、不抓取、不缓存上游会话 cookie 到我们自己的存储；
- 不在诊断里输出任何账号标识（只输出 `loggedIn: true/false`）。

## 已知边界（不是 bug，别去"修"）

- DSH 的 Web GUI 不能嵌进面板：跨源、没有会话深链、也没有 embed 参数；它的渲染组件拿不出来（`app.asar` 不可改）。所以"把 DSH 的对话框搬过来"这条路不存在，我们只搬**表达**。
- 上游快照不是字节级一致：**恰好 17 个文件**有本地改动，记录在 `vendor/official-shell/patch.diff`；打包器拒绝任何计划外的改动。
- 面板的"底部状态条"（缓存命中、步数、tokens）**故意没有**：那是 DSH 的观感，不是影片工作的观感。
