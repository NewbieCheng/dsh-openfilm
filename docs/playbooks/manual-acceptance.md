# 真机验收清单（发版前由人跑一遍）

> 面向 **0.15.1** 的真机验收：11 步，按顺序走一遍。
> 能自证的（单测、HTTP 路由、文件落盘）`npm run check` 已经跑过；**只有"浏览器里到底画出什么"必须由人看**。
> 任何一条不对：把那一条的编号 + 你看到的样子 + 该条「失败要贴」里要的东西发回来，据此修。

生效方式（每轮改完都做一次，`AGENTS.md` §4.1.1）：

```sh
npm run build F:/Dev/Desktop-Projects/dsh-openfilm     # 只有改了客户端源码才需要
```
1. `plugin_manager set_plugin enabled=false target=include:dsh-openfilm`
2. `plugin_manager set_plugin enabled=true  target=include:dsh-openfilm`
3. 浏览器 Ctrl+Shift+R 刷新
4. 看 `%TEMP%\dsh-openfilm-host.json` 的 `startedAt` 是否变新——**没变就是还在跑旧代码**。

> 下面按 11 步组织，每一步都已经写满，可以直接执行。

## 第 1 步 · 观测层

目的：把"右边什么都没有"拆成三种情况之一——**① DSH 没产出 → ② 桥接没发出 → ③ 发出但页面没收/没画**。

### 1.0 插件加载状态（先看这个）

- [ ] DSH 插件管理器里 `dsh-openfilm` 显示 **「运行中」**（绿点），不是「异常」。
- 如果显示异常：红字就是加载期报错原文。0.7.0 首次安装曾因工具输出 schema 里 `required` 写成属性级布尔而整包被拒（`unsupported JSON schema: … .required is not supported on type "string"`），已修复；若再出现同类文案，说明有工具 schema 写错，把它贴给我，并先跑一次 `node --test tests/tool-schema.test.mjs`。
- 重装/重载顺序：① 插件管理器里开关关掉再打开（会重新求值模块，通常够用）；② 仍异常则用命令行重装（把插件真正写进 profile）：
  ```
  "F:\apps\DSH_harness\resources\runtime\cli\bin\dsh.cmd" plugin --profile desktop add "link:F:\Dev\Desktop-Projects\dsh-openfilm" --offline
  ```
  成功会打印 `+ dsh-openfilm link:…`，并把 `dsh-openfilm` 同时写进 `~/.dsh/profiles/desktop/package.json` 的 `dependencies` 和 `dsh.profile.bundles`；③ 改完 profile 需要**重启 DSH 应用**才生效。
- **每次都要确认「当前版本」与 `package.json` 一致（仓库版本以 `package.json` 为准）。**

### 1.0.1 页面控制台没有红字

- [ ] 打开视频面板后按 F12，Console 里**不应**有红色报错，特别是 `is not a function`。
- 0.7.0 曾有一条 `(intermediate value)… is not a function`：注入的页面脚本两个 IIFE 之间漏了分号，被 ASI 连成调用链。已修（`assets/shell-ui.js` 第 707 行前补 `;`），并加了 `tests/shell-ui-asi.test.mjs` 用假 DOM 真跑一遍。
- 页面脚本按 mtime 读盘：**改完强刷即可（Ctrl+Shift+R）**，不需要重启 DSH。

### 1.1 确认新代码在跑

- [ ] 按上面 1–4 生效后，`%TEMP%\dsh-openfilm-host.json` 的 `startedAt` 比上一次新。
- 失败要贴：该文件全部内容（只有 version/pid/startedAt，无隐私）。

### 1.2 发一句会触发工具的话

右侧对话框照抄：

```
先读一下 film.html，再运行一条命令看看 node 版本，然后告诉我你改了什么
```

- [ ] 等它跑完（或明显卡住 15 秒以上，也可以直接进下一步）。
- 失败要贴：这期间右侧**截图一张**（有卡住的样子最好）。

### 1.3 抓三路证据

```sh
curl -s -X POST http://127.0.0.1:12417/api/no996-openfilm/diagnose ^
  -H "content-type: application/json" -b "%USERPROFILE%\.dsh\cookie.txt"
```

> 端口以你当前 DSH 地址为准。拿不到 cookie 就退一步：把 `%TEMP%\dsh-openfilm-frames.jsonl` 发我（**每轮覆盖写，发之前别发新消息**）。

- [ ] `diagnose` 返回里 `bridge` 这一段（新加的）。
- [ ] `%TEMP%\dsh-openfilm-frames.jsonl`。

### 1.4 判定表（我按这张表定结论，你也可以自己看）

| `bridge` 里的样子 | 说明 | 下一步修哪里 |
|---|---|---|
| `emitted: 0`（frames 里有 `tool/call`） | 桥接**没翻译出任何事件** | 第 4 步 act 词典 / 帧解析 |
| `emitted > 0` 且 `refused > 0` | 发出去了，但**没有活着的面板流接收** | 面板事件流与会话 |
| `emitted > 0`、`refused: 0`、`panel.seen: 0` | 页面**没上报计数**（可能没收到） | 追踪上报通道 |
| `panel.seen > 0` 且 `kinds` 有值、右侧仍空白 | 页面**收到了**，是**壳子不画** | 第 4 步 act 词典 |
| `panel.seen` 明显小于 `accepted` | 中间丢帧（背压） | 事件流 |

- [ ] 把命中那一行的结论回我一句（或直接贴 §1.3 两段，我判）。

### 1.5 顺带记录（不用修，第 4 步才修）

- [ ] 右侧每次工具调用是不是都塌成同一句「正在处理」，且没有文件名/命令行。

## 第 2 步 · 完全访问

目的：**进入就只问一次**，之后跑命令、写文件、导出都不再被打断；而且随时能改回来。

### 2.1 第一次进项目

- [ ] 打开任意一个 OpenFilm 项目（`/projects/<id>`）。约 1 秒内，页面顶部中间应出现一张卡：**「视频剪辑要一次权限确认」**，正文说明"要写文件、跑命令、调渲染和导出"。
- [ ] 底部中间同时有一个小胶囊按钮显示当前权限。
- 失败要贴：整页截图 + `/diagnose` 的 `permission` 段（见 2.5）。

### 2.2 点「允许并继续（完全访问）」

- [ ] 状态行先显示"正在应用…"，随后变成"已应用：完全访问"（若此时还没会话，则显示"已记住：…发第一句话即可"）。
- [ ] 卡片自动消失，底部胶囊变成 **「权限：完全访问」**。
- 失败要贴：状态行的原文（它带着错误码：`PERMISSION_UNAVAILABLE` = 这个 DSH 版本不允许插件改；`PERMISSION_SESSION` = 还没会话）。

### 2.3 确认真的不再问

在右侧发：

```
运行 echo ok 看看当前是哪个目录
```

- [ ] 命令**直接跑完**，中途没有出现任何审批提示。
- [ ] 左侧 DSH 那边同一个会话里，权限显示为 `danger-full-access`（或至少不再弹审批）。

### 2.4 刷新与换项目不重复问

- [ ] 刷新页面 → 不再弹卡，胶囊仍显示「权限：完全访问」。
- [ ] 换到另一个项目 → 那个项目**单独**弹一次（按项目记，不串）。

### 2.5 改回工作区

- [ ] 点底部胶囊 → 卡片重新出现 → 选「只用工作区」→ 胶囊变成「权限：工作区（关键步骤会询问）」。
- [ ] 再让它跑一条会越界的命令（例如写 `C:\temp\probe.txt`）→ DSH 侧应恢复询问。
- 失败要贴：`curl -s -X POST http://127.0.0.1:12417/api/no996-openfilm/diagnose -H "content-type: application/json"` 返回里的 `permission` 段。

### 2.6 这一步的判定

| 现象 | 结论 |
|---|---|
| 卡不出现 | `permission.available=false`（DSH 版本没暴露预设）或 `decided` 已是 true |
| 点了「允许」但下一次仍在问 | 该 Session 没被应用：看 `permission.names` 里有没有 `danger-full-access` |
| chip 一直"未设置" | 会话还没建（先发一句话） |

## 第 3 步 · 模型与思考强度 / CLI 上下文

目的：① 这个模式用哪个模型、思考多重，**在面板里就能选**；② 模型知道 `openfilm` CLI 在哪个绝对路径、该怎么调。

### 3.1 模型菜单来自 DSH 实时注册表

- [ ] 打开项目，点输入框附近的模型菜单：分组与模型应与 DSH 左侧「模型」菜单一致。
- [ ] 换一个模型 → 刷新页面 → 仍是换过的那个。

### 3.2 思考强度是一等选项

- [ ] 同一个菜单里出现 **「思考强度」**，选项含 **「自动（按这一句话的内容）」** + 该模型声明的档位（如 低/中/高）。
- [ ] 换到不支持思考的模型 → 这一项**消失**（不是灰着，是不显示）。

### 3.3 自动档真的会变

- [ ] 在新项目发第一句普通的话（例："看看这个项目现在有什么"）→ 打开菜单，当前值应是**最低档**（起稿档）。
- [ ] 再发："把整片重新剪成 30 秒" → 当前值应变成**最高档**。
- [ ] 手动选「低」→ 之后再说"整片重排" → 仍是**低**（手动选择优先，不被自动覆盖）。

### 3.4 模型自己知道 CLI 在哪

在右侧发：

```
openfilm 的命令行工具在哪个绝对路径？应该怎么调用？先说清楚再跑一下 doctor
```

- [ ] 它报出的路径形如 `…\dsh-openfilm\node_modules\openfilm\bin\openfilm.mjs`（**真实存在的绝对路径**，不是占位符、不是 `npx`）。
- [ ] 它给出的命令模板是 `node "<该路径>" <verb>`，并要求 cwd = 项目目录。
- [ ] 让它跑 `doctor`：完全访问模式下应能跑出结果（首次可能较慢）。
- 失败要贴：它实际报的路径与命令原文。

### 3.5 判定

| 现象 | 结论 |
|---|---|
| 菜单里只有模型没有思考强度 | 当前模型没声明 `reasoning.efforts`，或 `agent:thinking` 未通 |
| 思考强度里只有"自动" | 同上；不是丢档，是这个模型本来没有 |
| 报的 CLI 路径不存在 | 插件依赖树里没有 `openfilm`（`npm ls openfilm` 查） |

## 第 4 步 · 呈现层

目的：右侧每一行都能看懂它在干什么、动了哪个文件；失败能看出来；计划能逐项打勾。

### 4.1 读文件

在右侧发：

```
先读一下 film.html，告诉我第一行是什么
```

- [ ] 出现 **「正在读取文件 · film.html」**（带文件名），旁边是思考折叠区。
- [ ] **不是**一句「正在处理」。

### 4.2 跑命令

```
运行 node -e "console.log(1)" 看看输出
```

- [ ] 出现 **「正在运行命令 · node -e …」**（能看到命令行本体）。

### 4.3 搜索

```
在项目里搜一下所有 .mjs 文件
```

- [ ] 出现 **「正在搜索文件 · *.mjs」**（能看到 pattern）。

### 4.4 计划清单

```
这个任务分三步做：先看片、再改标题、最后导出。用 todo 记下来。
```

- [ ] 右侧出现**计划清单**（不是一张工具卡），条目与它说的三步一致。
- [ ] 它做一步，清单对应项变成"进行中/已完成"。

### 4.5 失败可见

```
读一下 一个不存在的文件.txt
```

- [ ] 那张卡变成**失败态**（红色/失败标记），不像什么都没发生。

### 4.6 历史还在

- [ ] 刷新页面 → 上面这些卡片与计划**仍在**（不是全空）。

### 4.7 判定

| 现象 | 结论 |
|---|---|
| 仍全是「正在处理」 | `kind` 没生效：贴 `diagnose.bridge.kinds` + 截图（看 `tool_call` 是否到达） |
| 有「正在读取文件」但没有文件名 | `rawInput` 还是被当成字符串用了；贴那一行截图 |
| 计划清单没出现 | 模型没调 `todo_write`，或参数里没有 `todos` 数组 |

## 第 5 步 · 审批与打断

> 这一步**必须在工作区模式**下测（第 2 步改回「只用工作区」），因为完全访问模式根本不会有审批——那本身也算通过。

### 5.1 审批出现在右边

- [ ] 先按第 2 步把权限改回 **「只用工作区」**。
- [ ] 在右侧发一句会越界的话，例如：

```
在 C:\temp 下写一个 probe.txt，内容是 ok
```

- [ ] 右侧出现**确认卡**（允许一次 / 拒绝），同时上方有一行提示「需要你在画面这一侧确认」。
- [ ] 点「允许一次」→ 命令继续跑完。
- 失败要贴：右侧截图 + `%TEMP%\dsh-openfilm-frames.jsonl`。

### 5.2 两边都能答，且只生效一次

- [ ] 再来一次同样的越界写。这次**去 DSH 左侧**点允许。
- [ ] 右侧那张卡应变成"已失效/无法回答"，但整个任务照常继续（**不能卡住**）。
- [ ] 反过来再来一次：右侧先答，左侧的卡随之消失或点击时提示已失效。

### 5.3 被打断 = 已停止，不是报错

- [ ] 发一句耗时长的话（例如"把整片重新剪一遍"），任务进行中在 **DSH 左侧**点停止。
- [ ] 右侧应在几秒内显示 **已停止**（不是红色错误、也不是一直转圈）。

### 5.4 插一句不炸

- [ ] 在一次长任务进行中，去 **DSH 左侧**输入框发一句话。
- [ ] 右侧应出现一行提示「你在 DSH 那边插了一句…」；**本轮不中断**，仍然把当前的活跑完。
- [ ] 之前的表现是整轮直接失败（`OFFICIAL_AGENT_CONFLICT`）——那个现象不该再出现。

### 5.5 判定

| 现象 | 结论 |
|---|---|
| 越界写直接失败、没有卡 | DSH 侧策略不是 `ask`（在 DSH 里检查权限预设） |
| 有卡但点了没反应 | `agent:answer-permission` 未通，或 key 已过期（看 `diagnose.bridge.tail`） |
| 点了右侧，左侧卡还在 | 正常（我们改不了 DSH 自己的 UI）；再点左侧会得到"已失效" |
| 停止后右侧报错 | `aborted` 没被归一（贴右侧原文） |

## 第 6 步 · 看得到

> 0.9.0 新增三条要一起看：工具行右侧的**真名标**（`openfilm_frame` / `web_search`）、**抽帧的图直接画在对话里**（点击放大）、**没有文本的思考不出现空块**。

目的：agent 能**看见画面**、**读懂结构**、**引用库里现成的动效**，而不是靠猜 film.html。

> 这一步全部走「已在跑的 Studio」，不需要 CLI、不需要 Chrome：
> `GET /api/projects/:id/media?path=film.html&what=frame|poster|probe` 就是 Studio 自己用 Chromium 画出来的那一帧。

### 6.1 它真的看得到画面

在右侧发：

```
把第 2 秒的画面渲染出来给我看，然后告诉我画面上有什么
```

- [ ] 右侧出现 **「正在预览影片」/「正在查看画面」**，随后**一张真实的图片**（不是占位符）。
- [ ] 它描述的**和图片一致**（文字可读、位置对得上）。
- 失败要贴：右侧截图 + 那句话的原文（它若说"看不到画面"，说明模型没有读图能力：换成支持图像的模型再试）。

### 6.2 它读得懂影片结构

```
这个片子现在有几条轨、几个片段、哪条轨锁了？
```

- [ ] 回答里的轨数/片段数与 Studio 左侧时间轴**一致**。
- [ ] 锁定的轨道它能说出来。

### 6.3 它会不会引用动效库

```
从库里找一个柔和的转场，用在片子开头，并告诉我你取了哪一个
```

- [ ] 它先列出几条候选（带 id），然后把其中一条**取进项目**。
- [ ] Studio 的素材面板里能看到那个文件。
- [ ] 它没有编造素材名——对照 Studio 里真实存在的文件。

### 6.4 没连生成服务时说人话

```
用 tts 给我配一句旁白
```

- [ ] 如果没连服务：它**明确说"这台机器没连生成服务，要去 Studio 设置里连"**，并**不重试**、也不假装生成了文件。
- [ ] 如果已连：返回真实生成的文件路径。

### 6.5 判定

| 现象 | 结论 |
|---|---|
| 「看不到画面」 | 当前模型不支持读图（工具会明说），换模型 |
| 画出来的图是黑的/空的 | film.html 那一秒本来就没内容，或 `probe` 报 404/422（贴工具输出） |
| 结构对不上 | Studio 缓存未刷新，刷新页面重试一次 |
| 库里搜不到 | 换关键词或换类别；这个库是离线的标签匹配，不含语义模型时匹配较窄 |

## 第 7 步 · 落盘编辑与上传入库

> 这一步会**真的改 film.html**。先在 Studio 里手动保存一次（Ctrl+S），再让 agent 改，才不会把未保存的手动改动压掉。

### 7.1 一次真的时间轴编辑

在右侧发：

```
把第一个视频片段往后挪 2 秒，然后告诉我你改了哪个属性
```

- [ ] 右侧出现 **「正在剪辑/正在修改」** 类动作，不是"正在处理"。
- [ ] 改完后 **Studio 时间轴自己动了**（不用刷新；Studio 的文件监听会重载）。
- [ ] 用文本编辑器看 film.html：**只有那一个 `at=` 变了**，注释、`<style>`、其它片段逐字节不变（这就是"最小 diff"）。

### 7.2 冲突时不硬写

- [ ] 先在 Studio 里手动拖一个片段（不保存也可以，保存更好），然后马上让 agent 改同一段。
- [ ] 预期：它**拒绝**并说"文件已经变了，现在是 xxx，你手上是 yyy，重新读一遍再改"，**文件没有被覆盖**。

### 7.3 锁定轨道被拒

- [ ] 在 Studio 里锁住一条轨，然后让 agent 把片段挪到那条轨。
- [ ] 预期：明确说"冲突——目标轨道是锁定的"，文件不动。

### 7.4 上传的素材能用

- [ ] 把一张图**拖进右侧聊天**（或让它用 `openfilm_assets` 导入一个本地文件）。
- [ ] 预期：Studio 素材面板里出现该文件；它给出的相对路径能直接写进 film.html 并渲染出来。
- 失败要贴：`assets` 面板截图 + 工具返回的那段文字。

### 7.5 判定

| 现象 | 结论 |
|---|---|
| 改完 Studio 不动 | Studio 的文件监听没触发，手动刷新一次；若仍不变，贴工具返回的"已保存"文本 |
| 其它内容被改写 | 不是最小 diff，必须贴 before/after 片段 |
| 冲突时仍然写了 | 严重 bug：贴两份文件内容 |
| 上传后素材面板没有 | 走的是本机拷贝而不是 Studio 路由（看工具返回的"已入库"路径） |

## 第 8 步 · 一句话出片与导出

这是**总验收**：从零开始，用一句话走完全程。

### 8.1 空白草稿 → 一句话

- [ ] 在 Studio 左侧**新建一个空白草稿**（或选一个模板）。
- [ ] 右侧（桥接对话）应**自动**接上这个项目（不需要你手动开对话）。
- [ ] 在右侧输入一句话，例如：

```
做一个 15 秒的竖屏短片，讲一只猫在雨天等主人回家，配一段轻音乐
```

- [ ] 它**直接开工**（不再反问你五个问题），右侧逐步出现：思考 → 看画面 → 改时间轴 → 计划清单。
- [ ] 中途你**不做任何操作**，它应当自己走到结束。

### 8.2 它真的看见了自己做的东西

- [ ] 过程中至少出现一次**真实画面图**（不是占位符）；它对这些画面的描述与图一致。
- [ ] 它引用库里素材时，Studio 素材面板里确实有那些文件。

### 8.3 导出并核对文件

- [ ] 让它导出，例如：

```
导出成 1080p 的 mp4 给我
```

- [ ] 右侧出现 **「正在导出」** 类动作。
- [ ] 它给出的**文件路径真实存在**（去资源管理器打开/播放）。
- [ ] 若它说"导出不了"，应同时说明原因（缺 ffmpeg / 没连服务 / 编码不支持），**不是含糊的失败**。
- 失败要贴：右侧原文 + `%TEMP%\dsh-openfilm-frames.jsonl` 里最后 30 行。

### 8.4 CLI 兜底可用（可选）

- [ ] 让它跑 `openfilm doctor`（或它自己判断需要时去跑）。
- [ ] 返回的是真实体检输出（Node/ffmpeg/Chrome 版本之类），不是模拟。

### 8.5 判定

| 现象 | 结论 |
|---|---|
| 一句话后它反复追问 | 预设提示词没生效（检查第 3 步 3.4） |
| 全程没有画面 | 第 6 步没过 |
| 承诺导出但没有文件 | **严重**：贴它的原文 + `openfilm_export status` 的输出 |
| 中途卡在确认 | 第 5 步没过 |

## 第 9 步 · 本地口播转写（0.10.0）

目的：确认「丢一个口播视频过来 → 出带时间码的文稿 → 按段剪」这条链路在**用户自己这台机器**上真的走通。

### 9.1 新机器上的安装体验

- [ ] 在没装过模型的机器上（或把 `$DSH_HOME/no996-openfilm/models` 挪走）说「把这个视频的文稿提出来」，给它一个真实短视频。
- [ ] 它**先说**在下载约 228 MB 的语音模型，然后这一轮不被卡死（回一个结果，不是长时间无响应）。
- [ ] `openfilm_transcribe({status:true})` 能看到百分比与目录；下载完成后 `ready: true`。
- [ ] 下载中断（拔网线再连）后重试仍能完成，且**不会**出现「看着就绪但识别报错」的半份模型。

### 9.2 转写质量与时间码

- [ ] 返回里有 `[mm:ss.d–mm:ss.d] 文本` 的逐段列表，且时间与视频对得上（拖动到该时间，确实在说这句话）。
- [ ] 段数不是「一段长条」：有停顿的口播应被切成多段。
- [ ] `校对：` 一行写着会话模型已校对；项目名/人名被纠正过。`refine: false` 时写「已跳过」。
- [ ] `.openfilm/transcripts/<key>.json` 真实存在，含 `segments` 与 `sentences`。

### 9.3 拒绝路径

- [ ] 一个没有音轨的录屏 → 明确说「这个文件没有音轨」，不是笼统失败。
- [ ] 超过 3 小时的音轨 → 明确拒绝并给出分钟数与切段建议（不要真的跑）。
- [ ] 纯音乐/静音 → 「没有听到人声」，不是空结果当成功。

### 9.4 判定

| 现象 | 结论 |
|---|---|
| 一直停在「下载中」 | 网络/镜像问题；换 `NO996_OPENFILM_ASR_BASE_URL` 或预置权重 |
| 有文稿但时间码全 0 | pipeline 段界没写回；贴返回原文 |
| 中文出现大段英文乱码 | 语言参数被误设；试 `lang: "zh"` |
| 识别到一半会话超时 | 音轨太长；先切段，并参考 ROADMAP「转写搬进 Worker」 |
